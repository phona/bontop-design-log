# 专业买手报告契约

`shopping-research` 的交付不是商品列表，也不是交易指令。每次交付都使用以下固定结构；没有事实时写“未知/未验证”，不要删除栏目或用评分掩盖不可比性。

## 1. 执行摘要

用短段落说明：需求目标、最重要的硬约束、探索是否收敛、推荐与备选各自适用条件、最大风险、阻塞平台和用户下一步。明确报告不代替用户交易。

## 2. 需求与口径

列出：

- `hardConstraints`、`preferences`、`budget`、`taboos`、`unknowns`；
- 地区、配送/税费假设和比较单位；
- 哪些是用户明确要求，哪些是研究阶段推断；
- 价格口径：展示价、明确 SKU 价、券价、MOQ、阶梯价、运费是否可比。

## 3. 探索覆盖

记录平台和基础 Skill 是否可用、查询矩阵、实际页码/排序/抽样、详情读取深度、时间/导航/详情预算使用情况，以及每个分支的 `status`。明确停止原因：信息增益低、结果收敛、阻塞或预算耗尽。

推荐证据对象形状：

```json
{
  "platform": "jd",
  "kind": "search|detail",
  "url": "页面 URL",
  "observedAt": "ISO-8601",
  "status": "ok|authentication_required|security_verification|site_blocked|layout_changed|no_results",
  "field": "items[0].price.raw",
  "note": "该事实如何支持结论"
}
```

URL、时间和状态必须来自实际观察；状态阻塞时不要生成虚构商品证据。

## 4. 候选对比

用表格保留原始字段和口径，不强行压成单一分数。建议列：候选/平台/商品 ID/标题/店铺或公司、规格与单位、展示价、明确 SKU 价、券价、MOQ、阶梯价、运费、销量文本、广告标记、库存/配送、证据、状态、事实/推断/未知、淘汰或保留理由。

不同平台或不同 SKU 无法在同规格、同单位、同地区和同费用口径下比较时，单元格明确写“不可直接比较”，并说明缺少什么；禁止使用拍脑袋换算或隐含假设评分。

## 5. 推荐与备选

推荐必须绑定适用条件和证据：满足哪些硬约束、价格口径是什么、哪些字段仍未知、为什么新增探索不太可能改变结论。备选应说明与推荐的取舍，例如更低展示价但 MOQ/运费未知，或更稳定规格但促销不可核验。没有足够证据时输出“暂不推荐/需要补充信息”，不要强选一个。

## 6. 淘汰项

按候选列出可回溯理由：硬约束不满足、疑似重复、SKU/单位不明、展示价不可比、页面阻塞、广告仅展示、详情缺口或预算停止。不要把“没有 reviews”写成负面口碑；只写口碑、耐用和售后体验未验证。

## 7. 风险与未知

集中列出登录/安全验证/站点阻塞、页面布局缺口、SKU 未解析、MOQ/阶梯价/运费/税费/配送未知、同款归并不确定、广告标记和所有未验证体验。每项尽可能绑定证据与影响范围。

## 8. 用户下一步核验

给用户可执行的只读或人工确认事项：确认规格/单位/收货地、手工验证登录或 CAPTCHA、查看最终运费/税费/促销有效期、确认 SKU、向供应商确认 MOQ/阶梯价/交期，以及在用户自行决定后再进行交易。不得替用户点击购买、加购、收藏、下单或支付。
