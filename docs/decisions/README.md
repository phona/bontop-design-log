## 归档纪律（新增条目前必读）

1. **一条 DEC 只进一个文件**，按「改动的主战场」定归属，不按提到的所有域定。
2. 编号仍按日期发放，与文件无关；`c.dec_unique` 跨 18 个主题文件与 1 个归档分册文件查重（清单见 `config/facts.yaml` 的 `x_decision_files`），重号照样报 error。
3. 新条目**追加到对应主题文件末尾**，不新建文件；单文件超过 80 KB 才考虑再拆。
4. 反查编号用 `grep -rn "DEC-xxxx" docs/decisions/`；本索引只维护「文件 → 区间」19 行（18 个主题文件 + 1 个归档分册），
   不做全量 177 行编号表，避免出现第二份真相。
5. 历史条目**只登记不改写**：发现旧条目写错，新登记一条修正 DEC，不改旧正文。
6. **不要重跑拆分脚本**：`tmp/split-decision-log.py` 是一次性迁移工具（输入已删除的
   `docs/decision_log.md`），重跑会用旧映射表重建当初那批文件，抹掉拆分后新增的条目
   （如 `DEC-2026-10-09-S01`）。新增条目一律手工追加到对应主题文件末尾。
