# 渲染管线技术债清单（2026-08-23 盘点）

> 来源：v17→v32 渲染修复轮 + 双 subagent 巡检（设计风格/贴图模型玻璃）。
> 用途：每轮迭代对着销账；丢给 AI 时直接指到条目。
> 状态标记：⬜ 未动 / 🔧 部分缓解 / ✅ 已解决（保留备查）

## A. 系统性问题（用户点名：东改一块西改一块的根因）

- ⬜ **A1 无全机位回归机制**：改灯光/材质只冒烟验证局部机位，客厅修好卧室漏掉。
  方案：每版渲染后自动跑 27 张的统计断言（黑区占比、过曝占比、与上版 diff 图），
  异常机位自动列出。这是防"修一处漏一处"的根。
- ⬜ **A2 链路未自动化**：配置 → GLB 导出 → 上传 → 渲染 → 拉回 全程手工串。
  GLB 导出 2026-08-23 才用 agent-browser 打通（patch createObjectURL 截 blob 分块读出），
  尚未固化成脚本。方案：一条命令跑完全程。
- 🔧 **A3 巡检靠人眼**：双 subagent 巡检是临时编排，无固定的"机位验收清单"
  （每个机位应该看到什么、不该看到什么）。方案：写进 config 的每机位验收断言。

## B. 架构债

- ⬜ **B1 dress_scene.py 1600+ 行单文件**：建模/材质/灯光/相机/渲染循环一体，
  工况特殊处理靠 if 分支堆积（sheer_state/glass_ior/fill_from_camera/blackout_state…）。
  方案：工况收敛为声明式能力表，渲染循环只查表。
- ⬜ **B2 配置/代码边界模糊**：曝光在工况+相机两层、灯瓦数在代码常量、色板坐标在渲染配置、
  家具摆位在 house.yaml。方案：定一条"哪层管什么"的线并写进 AGENTS.md。
- ⬜ **B3 Blender 侧无对象注册表**：靠命名约定（classify 模式匹配），新增对象类型要同步
  classify/collision/导出白名单多处。方案：对象类型注册表单点定义。
- 🔧 **B4 几何重复墙无校验**：共面重复墙导致 Cycles 阴影自遮挡黑墙（书房/厨房已修），
  但 verify-topology 对重复墙段只报 info 不 fail。方案：重复墙检测升级为 error。
